# Агенты на моделях профиля: дизайн

Дата: 2026-11-25. graft v0.3.0, Claude Code 2.1.331.

## Зачем

Владелец хочет для некоторых задач держать оркестратором Opus, а реализацию отдавать другим моделям, например ChatGPT. Внешние модели в сессии graft уже есть, но передать им подзадачу нельзя: параметр `model` инструмента Agent принимает только `opus`, `sonnet`, `haiku` и `fable`. Агент с внешней моделью в определении работает, но его надо описать руками, и Claude не знает, какие модели у сессии есть.

## Цели

1. В сессии graft Claude запускает субагента на любой внешней модели профиля. Настраивать ничего не нужно.
2. Claude знает эти модели: имя, `label`, `description` и как запустить на них агента.

## Не цели

- Роли, инструменты, effort и тексты «для чего» по агентам: поле `agents` в конфиге и формы `graft ui`. Их можно добавить позже, ничего не ломая.
- Назначать Opus оркестратором. Это делает владелец: словами, в CLAUDE.md, в плане или через `--append-system-prompt` в `args` профиля.
- Подменять модель, если её провайдер недоступен. Агент возвращает ошибку, дальше решает оркестратор.

## Провалом было бы

- Claude сам, без указания, отдаёт работу внешней модели.
- Работа агента внешней модели молча уходит на Claude.
- graft пишет файлы Claude Code или теряет `--agents` пользователя.

## Ограничения

- Из двух `--agents` Claude Code берёт последний, из двух `--append-system-prompt` тоже. Поэтому `--agents` graft передаёт один, а `--append-system-prompt` не занимает.
- До 2.1.327 агенты из `--agents` терялись после загрузки плагинов.
- `--agents` виден в списке процессов. Секретов в нём нет: имена, `label`, `description`.

## Подходы

| Подход | Плюсы | Минусы |
| --- | --- | --- |
| **A. graft сам строит `--agents` из внешних моделей профиля** | из коробки; ничего на диске; одинаково напрямую и за роутером; список строится заново при каждом запуске, включая `--resume` | агентов нельзя настроить по отдельности; агент graft перекрывает одноимённый из `~/.claude/agents` |
| B. Поле `agents` в конфиге | модели, тексты и effort на каждый профиль | заполнять в каждом профиле; проверка конфига, формы и тесты `graft ui` |
| C. Плагин graft через `--plugin-dir` | имена `graft:sol` не пересекаются с чужими; `--agents` пользователя не затронут | файлы на диске; в прямом режиме graft заменяет себя на claude и не может их убрать |

Отброшены: `aliases: {sonnet: sol}` (забирает у сессии Sonnet, на который рассчитывают другие агенты, и Claude считает модель Sonnet) и таблица моделей в `--append-system-prompt` (занимает флаг, нужный владельцу).

Владелец выбрал **A**: он закрывает задачу целиком, а поле из B ляжет сверху.

## Как это устроено

**Когда есть агенты.** Когда сессии есть из чего выбирать: у профиля есть внешняя модель и подписка или не меньше двух внешних моделей. Агентом становится каждая модель из `config.ExternalModels`, основная тоже: сессию `sol-plus` можно переключить на Opus. В остальных профилях ничего не меняется.

**Определение.**

| Поле | Значение |
| --- | --- |
| имя | имя модели в конфиге, в обоих режимах |
| `model` | `seen()`: имя за роутером, `id` напрямую |
| `description` | см. ниже |
| `prompt` | см. ниже |
| `effort` | уровень, с которым стартует сессия: последний `--effort` из `args` и командной строки, иначе `effort` профиля или `defaults`. Нет уровня или он не из `config.Efforts` — поля нет |

Без `effort` в определении субагент на другой модели получает `high`, а не `max` профиля. `maxEffortLevel` модели по-прежнему ограничивает уровень, а её `autoCompactWindow` из `modelSettings` действует и в субагенте, поэтому других полей не нужно.

**Описание** (точка в конце `description` модели убирается):

```
General-purpose agent on <label>: <description>. Use it when the user or their instructions ask for this model. Call it without `model`: a `model` in the call would replace <label>.
```

**Промпт с подпиской:**

```
This agent runs on <label> and on no other model. Before anything else, look at the model that your environment section says you are powered by. If its ID starts with `claude-`, the call that started you replaced the model by mistake: use no tool, leave the task undone, and reply with this one line only: "Wrong model: this agent runs on <label>. Call it again without `model`."

Otherwise, do the task in the message you got with the tools you have. Complete it fully: don't gold-plate, but don't leave it half-done. You are the agent for this task: do the work yourself, and do not hand the whole task to another agent. When you are done, reply with a concise report of what you did and what you found: the agent that started you reads only your reply.
```

Без подписки первый абзац — `This agent runs on <label>.`, а второй начинается с `Do the task`: алиасы там указывают на внешние модели, и `claude-` в ID может быть у своей же модели в прямом режиме.

**`--agents` в argv.** graft ставит его после `--settings`, перед `args`. Если `--agents` задан в `args` или в командной строке (до `--`) и это объект JSON, graft убирает его оттуда и передаёт один общий: при совпадении имён побеждает определение пользователя. Если это не объект JSON (путь к файлу, который Claude Code берёт с `-p`), graft оставляет аргументы как есть и своих агентов не добавляет.

**`--dry-run` и Preview.** После `settings` печатается раздел `agents` с тем же JSON, если агенты есть.

**Версия.** Минимальная — 2.1.327: `minClaude` в `graft check` и README.

**Документация.** README: раздел об агентах (что это, как попросить, effort, оркестратор на Opus, выключение через `settings: {permissions: {deny: ["Agent(sol)"]}}`, свой `--agents`, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` отменяет модели агентов, провайдер видит то, что читает его агент), строки в «How it works», `description` в таблице моделей. `config.example.yaml`: профиль с оркестратором. В `graft ui` меняется одна подсказка — у поля Description.

## Решения

Владельца: цель и сценарий; работа уходит внешней модели только по указанию, откуда бы оно ни пришло (слова, CLAUDE.md, план, навык); подход A; ветка через `git switch -c`.

Мои, владелец согласился в общих чертах: агент универсален; имя агента — имя модели; effort сессии; страховка в описании и промпте; объединение `--agents`; без новых полей конфига; минимальная версия 2.1.327.

Мои, новые в этом документе: агентов нет там, где выбирать не из чего; страховка в промпте только с подпиской; путь к файлу в `--agents` заменяет агентов graft; имя модели, совпавшее с именем встроенного агента (`Explore`, `Plan`), его перекрывает — об этом только README.

## Исполнителю

Раскладка по файлам, имена функций, устройство тестов, формулировки README. Тексты `description` и `prompt` выше менять только с повторной живой проверкой.

## Приёмка

На конфиге владельца, с профилем, где есть подписка и внешние модели:

1. `graft --dry-run <профиль>` показывает агента на каждую внешнюю модель с `effort` профиля; в профиле с одной внешней моделью без подписки агентов нет и argv прежний.
2. `graft <профиль>`, `/model` → Opus: на вопрос о доступных моделях Claude перечисляет агентов.
3. «Отдай это агенту <имя>»: в `~/.local/state/graft/graft.log` строка `model=<имя> route=<провайдер> status=200`, в `/tasks` видна модель.
4. «Запусти его с model: opus»: агент отвечает `Wrong model: …`.
