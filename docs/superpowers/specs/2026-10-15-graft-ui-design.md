# graft ui: дизайн

Дата: 2026-10-15. graft v0.1.0, Go 1.26.

## Зачем

Конфиг graft — YAML-файл, и править его можно только в редакторе. Новичку для первого запуска надо знать схему, Anthropic-совместимый адрес провайдера, ID модели, её окно контекста и где хранить ключ. Тому, у кого конфиг уже есть, приходится помнить поля и проверять ссылки между записями.

`graft ui` открывает в браузере редактор того же файла. Он дополняет ручную правку и не заменяет её: файл остаётся источником истины, его по-прежнему правят руками. Интерфейс рассчитан на всех пользователей graft, включая тех, у кого конфига ещё нет.

Имя `ui` зарезервировано под эту команду с этапа 2 graft: профиль так назвать нельзя.

## Сценарии и критерии готовности

Сценарии:

1. Новичок без конфига: `graft ui` → пресет провайдера → ключ → тестовый запрос → модели → профили → Save → `graft <профиль>`.
2. Повседневная правка: добавить, поменять, переименовать или удалить провайдера, модель или профиль, поправить `defaults`.
3. Файл правят в редакторе, пока интерфейс открыт.
4. Проверка до запуска: что запустит профиль, читается ли ключ, отвечает ли модель.

Критерии успеха:

- Новичок без конфига за несколько минут доходит до работающего `graft <профиль>`, не открывая README.
- Правка через интерфейс не мешает ручной: комментарии остаются на месте, файл остаётся удобным для правки руками.
- Интерфейс не может сохранить конфиг, который graft отвергнет.
- Другой пользователь машины или веб-страница не могут прочитать или изменить конфиг через сервер интерфейса.
- Ключ не попадает ни в конфиг, ни в браузер, ни в вывод graft.

Этап 1 (редактор) готов, когда:

- `graft ui` открывает редактор для существующего, отсутствующего и сломанного конфига;
- правки всех четырёх разделов сохраняются, комментарии переживают сохранение, а сохранённый файл проходит `graft check`;
- конфиг с ошибками сохранить нельзя, ошибки видны у полей;
- ручная правка при открытом интерфейсе обнаруживается: без несохранённых правок интерфейс перечитывает файл, с ними показывает конфликт;
- сервер отказывает запросам без токена, с чужим `Host` или `Origin`, а на Linux — соединениям от процессов других пользователей;
- README описывает `graft ui`.

Этап 2 (новичок) готов, когда:

- на чистом `HOME` путь из сценария 1 проходит без README, и `graft <профиль>` работает;
- ключ не попадает ни в конфиг, ни в браузер, ни в вывод graft;
- Preview профиля совпадает с `graft --dry-run`, кроме ключей: их Preview показывает источником и не читает;
- в Quick start README есть `graft ui`.

## Архитектура

### Команда

```
graft [--config <путь>] ui
```

- Путь к конфигу ищется так же, как у остальных команд: `--config`, `GRAFT_CONFIG`, `$XDG_CONFIG_HOME/graft/config.yaml`, `~/.config/graft/config.yaml`.
- `ui` аргументов не принимает. `ui` обрабатывается до `config.Load`: отсутствующий или сломанный конфиг для него не ошибка.
- `graft ui` поднимает сервер на `127.0.0.1` со случайным портом, печатает адрес и открывает браузер. Работает до Ctrl+C или SIGTERM.

### Пакеты

```
internal/config/   без изменений по сути; Parse остаётся единственной проверкой конфига
internal/edit/     новый: YAML ↔ черновик, слияние, рендер; без I/O, как plan
internal/ui/       новый: HTTP-сервер, защита, API, запись файлов, пресеты, встроенная статика
internal/ui/static/  index.html, модули на Preact + htm, style.css, vendor/
cmd/graft/ui.go    команда ui
```

Изменения в существующих пакетах:

- `config`: экспортируются списки полей каждого раздела в порядке README, чтобы схема жила в одном месте, и проверка адреса провайдера (сейчас `checkURL`) для тестового запроса.
- `keys`: экспортируется проверка значения ключа (сейчас `badChar`) для вставленного ключа.
- `router`: экспортируется конструктор транспорта (сейчас `transport`), чтобы тестовый запрос ходил через тот же прокси, что и маршрутизатор.
- Текст `--dry-run` переезжает из `cmd/graft` в `internal/launch`, где уже есть `SessionValue`. Функция принимает план, путь к `claude` и функцию, которая показывает ключ провайдера. `--dry-run` передаёт в неё чтение ключа с отпечатком, Preview — описание источника без чтения.

Новых зависимостей Go нет: сервер на `net/http`, вендоренные файлы — статика.

### Этапы

1. **Редактор:** команда, сервер и защита, `internal/edit`, формы четырёх разделов, проверка на лету и режим каждого профиля, сохранение с версией, конфликтом и `.bak`, старт с пустого файла, README.
2. **Новичок:** пресеты, экран первого запуска и диалог «Add provider», виджет ключа с вставкой и проверкой, тестовый запрос, Preview, Quick start в README.

У каждого этапа свой план, своя приёмка и свой PR. План этапа 2 пишется после приёмки этапа 1, по его коду.

## Черновик: `internal/edit`

### Формат

Черновик — JSON, с которым работает браузер. Поля записаны так, как в файле, без подставленных значений по умолчанию.

```json
{
  "providers": [
    {"was": "ollama", "name": "ollama", "url": "https://ollama.com",
     "key": {"kind": "file", "value": "~/.config/graft/keys/ollama"}}
  ],
  "models": [
    {"was": "kimi", "name": "kimi", "provider": "ollama", "id": "kimi-k3",
     "context": "1048576", "label": "", "description": "",
     "settings": "maxEffortLevel: high\n"}
  ],
  "defaults": {"effort": "max", "settings": "", "env": [],
               "args": ["--allow-dangerously-skip-permissions"]},
  "profiles": [
    {"was": "mix", "name": "mix", "model": "opus", "subscription": "",
     "picker": ["sol", "glm", "kimi"],
     "aliases": {"opus": "", "sonnet": "", "haiku": "", "fable": ""},
     "subagents": "glm", "effort": "", "settings": "", "env": [], "args": []}
  ]
}
```

Правила:

- Скаляры — строки в том виде, как записаны. Пустая строка значит, что поля в файле нет. Поэтому неверное значение из файла (`context: abc`, `subscription: yes`) видно в форме вместе с ошибкой.
- `was` — имя записи в файле, по которому сервер отличает переименование от удаления и добавления. У новой записи `was` пустой.
- `key` — `kind` (`env`, `file`, `command` или пусто) и `value` в том виде, как записано: путь не раскрывается. Если в файле задано несколько источников, берётся первый в порядке `env`, `file`, `command`, а ошибку показывает `config.Parse`. Если `key` — скаляр, то есть сам ключ, вписанный в конфиг, черновик получает пустой `kind`: значение в браузер не уходит.
- `settings` профиля, `defaults` и модели — YAML-текст. Он принимает и JSON, как в документации Claude Code, а комментарии внутри живут в самом тексте.
- `env` — список пар `[имя, значение]` в порядке файла; пустое значение здесь значит `""`. `args` и `picker` — списки строк. `aliases` — все четыре алиаса, пустая строка значит, что алиас не задан.

### Когда формы не открываются

Формы работают, только если черновик может представить файл. Иначе интерфейс показывает ошибки и ждёт, пока файл поправят в редакторе. Так бывает, если:

- YAML не разбирается или в файле больше одного документа;
- корень, раздел или запись — не словарь;
- известное поле не той формы: список вместо строки, словарь в `picker` и так далее.

Неизвестное поле (`contxt:`) формам не мешает. Черновик его не видит, слияние его не трогает, `config.Parse` сообщает о нём, а сохранение заблокировано, пока поле не уберут руками.

### Слияние

На входе текст файла той версии, на которой работал браузер, его черновик и присланный черновик.

1. Текст разбирается в дерево `yaml.Node`. Пустой файл даёт пустой словарь.
2. Записи сопоставляются по `was`. Запись, которой нет в присланном черновике, удаляется вместе со своими комментариями. Если имя записи отличается от `was`, меняется значение узла ключа, и комментарии записи остаются.
3. Поля сравниваются с черновиком файла, и в дереве меняются только изменившиеся:
   - скаляр меняется на месте, его комментарии остаются;
   - список пересобирается в прежнем стиле (`[a, b]` или блоком);
   - `env` и `aliases` меняются попарно: пара с тем же именем сохраняет узел ключа;
   - `key` заменяется словарём с одним источником, в стиле прежнего узла;
   - `settings` заменяется деревом, разобранным из присланного текста;
   - поле с пустым значением удаляется, новое встаёт на своё место в порядке README.
4. Узлы, которых правка не коснулась, остаются как были: с комментариями, стилем, якорями и ссылками на якоря. Правка одного поля никогда не меняет другое через ссылку YAML:
   - перед правкой или удалением значения с якорем (`&x`) каждая ссылка `*x` получает копию прежнего значения, а якорь исчезает;
   - поле, которое само было ссылкой `*x`, получает при правке собственное значение.

   Иначе файл разошёлся бы с черновиком, который видит пользователь, и сохранение не прошло бы проверку из шага 4 раздела «Сохранение». Проверено на прототипе 2026-10-15.
5. Новые записи идут в конец своего раздела, порядок существующих не меняется. Новый раздел встаёт на своё место среди `providers`, `models`, `defaults`, `profiles`. Раздел, из которого удалили все записи, удаляется.
6. Новые узлы пишутся в стиле README: записи блоком, `key` как `{file: …}`, `picker` и `args` как `[a, b]`.

Переименование модели или провайдера обновляет ссылки на них в самом черновике, ещё в браузере: `model`, `picker`, `aliases` и `subagents` у профилей, `provider` у моделей. Места ссылок запоминаются, когда поле имени получает фокус и имя ещё принадлежит одной записи. Дальше каждая буква меняет именно их, поэтому промежуточное имя, совпавшее с чужим, не перетягивает чужие ссылки. Сервер видит эти поля как обычные правки.

### Рендер

Дерево кодирует `yaml.v3` с отступом 2. Затем перед каждым ключом верхнего уровня, кроме первого, ставится пустая строка. Если у ключа есть комментарий, пустая строка встаёт перед комментарием.

Последствие: первое сохранение из интерфейса переписывает файл целиком. Комментарии остаются, а пустые строки внутри разделов, выравнивание комментариев и пробелы внутри `{ }` пропадают. Длинные строки `yaml.v3` не переносит. Проверено опытом на `config.example.yaml` 2026-10-14.

## Проверка, сохранение и ручные правки

### Проверка на лету

Через 300 мс после правки браузер отправляет черновик и версию файла. Сервер делает то же, что при сохранении: слияние, рендер, `config.Parse`. Но не пишет.

- Ответ — ошибки в виде пути и сообщения. Номера строк не передаются: они относятся к тексту, который пользователь не видит.
- Если конфиг валиден, ответ содержит ещё режим, провайдеров и подписку каждого профиля (`config.ModeOf`, `ProvidersOf`).
- Если файл на диске уже другой версии, ответ — `stale`, без проверки.

### Сохранение

По кнопке Save или Ctrl+S. Кнопка неактивна, пока правок нет или есть ошибки. Ctrl+S действует, только когда кнопка активна. Сервер под мьютексом:

1. Читает файл. Если конфиг — симлинк, путь сначала раскрывается: запись идёт в файл, на который он указывает, и симлинк остаётся.
2. Сверяет sha256 файла с версией из запроса. Не совпало — 409.
3. Сливает черновик с деревом, рендерит текст и проверяет его через `config.Parse`. Есть ошибки — 422 со списком.
4. Строит черновик из нового текста и сравнивает его с присланным. `was` при этом не сравнивается, `settings` сравнивается по значению. Не совпало — 500, файл не меняется: ошибка слияния не должна попасть на диск.
5. Копирует прежний файл в `config.yaml.bak` рядом с ним, с теми же правами.
6. Пишет новый текст во временный файл в том же каталоге, делает `fsync` и `rename` поверх конфига, потом `fsync` каталога.

Права прежнего файла сохраняются. Новый файл создаётся с правами 0600, каталог — с 0700, если его нет. Ответ содержит новую версию и черновик из записанного текста: у переименованных записей `was` теперь новое имя.

### Ручные правки при открытом интерфейсе

Каждые 2 с браузер спрашивает версию файла. Сервер пересчитывает sha256, только если изменились размер или mtime.

- Если в браузере нет несохранённых правок, интерфейс перечитывает файл и показывает уведомление «reloaded from disk».
- Если правки есть, появляется баннер «The file changed on disk» с выбором: перечитать, и тогда правки в браузере пропадут, или продолжить без сохранения, например чтобы переписать свои правки. Save при этом отвечает 409.
- Если опрос не проходит, сервер остановлен: баннер «graft ui stopped, your unsaved changes are only in this tab». Больше страница к серверу не обращается, а Save выключена.

Слияния правок браузера с правками на диске нет.

### Пустой конфиг

Если файла нет, черновик пустой, а первое сохранение создаёт каталог и файл. `config.Parse` требует хотя бы один профиль, поэтому сохранить получится, когда профиль появится. Ошибка «at least one profile is required» стоит у раздела профилей.

## Сервер и защита

### Старт

1. Сервер открывает сокет на `127.0.0.1:0`. Не получилось — `graft: …`, код 1.
2. Создаёт токен сеанса: 32 байта из `crypto/rand`, в hex.
3. Печатает:

   ```
   graft ui: editing ~/.config/graft/config.yaml
   graft ui: open http://127.0.0.1:43117/#token=<токен>
   graft ui: press Ctrl+C to stop
   ```

   В сеансе SSH добавляет строку `graft ui: from another machine: ssh -L 43117:127.0.0.1:43117 <host>, then open the address above`. Номер порта при пробросе должен совпадать: сервер проверяет `Host`.
4. Открывает браузер: на macOS через `open`, на Linux через `xdg-open`, если задан `DISPLAY` или `WAYLAND_DISPLAY` и не задан `SSH_CONNECTION`. Вывод программы не идёт в терминал, её ошибка не мешает: адрес напечатан.

Токен стоит во фрагменте URL. Фрагмент браузер не отправляет ни на сервер, ни в `Referer`. Страница сразу убирает токен из адресной строки (`history.replaceState`) и хранит его в `sessionStorage` вкладки. Вторую вкладку открывают тем же адресом из терминала.

### Доступ

- API (`/api/…`) требует `Authorization: Bearer <токен>`. Токен сравнивается за постоянное время. Статика отдаётся без токена: секретов в ней нет.
- `Host` — только `127.0.0.1:<порт>` или `localhost:<порт>`. Это защита от DNS rebinding.
- `Origin`, если он есть, — `http://127.0.0.1:<порт>` или `http://localhost:<порт>`. CORS-заголовков сервер не отдаёт, поэтому чужая страница не может отправить `Authorization`.
- **Linux: соединения от процессов других пользователей сервер закрывает сразу после `Accept`.** Uid собеседника берётся из `/proc/net/tcp` и `/proc/net/tcp6`: это строка, где локальный адрес — порт клиента, а удалённый — порт сервера. IPv6-сокет, подключённый к `::ffff:127.0.0.1`, есть только в `tcp6`. Свой uid и root пропускаются, только если сокет клиента в состоянии ESTABLISHED: закрывающийся сокет ядро показывает с uid 0. Серверный сокет соединения тоже должен быть в состоянии ESTABLISHED, иначе клиент закрыл соединение до проверки, и оно получает отказ. Если строка клиента не найдена ни в одной таблице, соединение проходит: такое бывает у соединений из другого сетевого пространства, например у ретрансляторов. Отказ другому пользователю печатается в терминал один раз на uid, отказ закрытому соединению — один раз за сеанс. Если `/proc/net/tcp` не читается, graft при старте предупреждает, что не может проверить собеседников. Проверено на ядре 7.0 2026-10-15: без условий о состоянии и без `tcp6` проверку обходили ранний `close` и IPv6-сокет.

  Зачем это нужно: при автооткрытии URL с токеном попадает в аргументы `xdg-open`, а на Linux аргументы чужих процессов видны всем через `/proc/<pid>/cmdline`. Без этой проверки другой пользователь мог бы прочитать токен и записать в конфиг `key.command`, то есть выполнить свою команду при следующем `graft`.
- На macOS проверки нет: ядро не отдаёт аргументы процессов другого пользователя без root (`KERN_PROCARGS2`; так же ведёт себя, например, getargv: «only see processes running as the same user»).
- Заголовки всех ответов:
  - `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Здесь `data:` нужен иконкам Pico;
  - `X-Content-Type-Options: nosniff`;
  - `Referrer-Policy: no-referrer`;
  - у API ещё `Cache-Control: no-store`, у статики `Cache-Control: no-cache`.
- Тело запроса — не больше 1 МиБ. Тайм-аут заголовков — 10 с, как у маршрутизатора.

### API

| Метод и путь | Этап | Запрос | Ответ |
| --- | --- | --- | --- |
| `GET /api/config` | 1 | — | путь (`~/…`), есть ли файл, версия, черновик или `null`, ошибки файла со строками, можно ли открыть формы |
| `GET /api/version` | 1 | — | версия |
| `POST /api/validate` | 1 | версия, черновик | `stale`, ошибки, режимы профилей |
| `POST /api/save` | 1 | версия, черновик | 200: версия и черновик; 409: файл изменился; 422: ошибки |
| `GET /api/presets` | 2 | — | пресеты |
| `POST /api/key/check` | 2 | источник ключа (`kind`, `value`) | состояние, отпечаток, предупреждение или ошибка |
| `POST /api/key/write` | 2 | имя провайдера, ключ, `replace` | путь и отпечаток; 409, если файл есть и `replace` не задан |
| `POST /api/test` | 2 | `url`, источник ключа, `id` модели | статус, время, ответ или тело ошибки |
| `POST /api/preview` | 2 | версия, черновик, профиль | текст плана или ошибки |

Ошибки сервера приходят в виде `{"error": "…"}` с подходящим статусом.

### Остановка

По Ctrl+C или SIGTERM сервер закрывается: `Shutdown` с ожиданием до 2 с, код выхода 0. Страница замечает остановку при следующем опросе версии. Если закрыть вкладку с несохранёнными правками, браузер попросит подтверждения (`beforeunload`).

## Интерфейс этапа 1

Надписи интерфейса — на английском, как и весь вывод graft. Тема светлая или тёмная, по настройке системы.

### Раскладка

- **Верхняя панель:** путь к конфигу, состояние (`saved` или `● unsaved`) и счётчик ошибок. Щелчок по счётчику открывает список ошибок со ссылками на поля. Рядом кнопка Save.
- **Боковое меню:** разделы Providers, Models, Profiles и Defaults, у первых трёх кнопка «+». У профиля рядом с именем режим (`direct` или `router`), если конфиг валиден. У записи с ошибками — красный счётчик. «+» создаёт запись с именем-заготовкой (`provider-1`, `model-1`, `profile-1`), открывает её форму и ставит курсор в поле имени.
- **Основная область:** форма выбранной записи. В шапке формы имя, режим, подписка и провайдеры профиля, а также кнопка удаления.

### Формы

У незаданного поля серым показано значение по умолчанию, у полей есть подсказки по таблицам README.

- **Provider:** имя, URL и источник ключа — переключатель `env | file | command` и одно поле к нему. У нового провайдера источник — `file` с путём `keys/<имя>` рядом с конфигом. Пока путь не трогали, он следует за именем провайдера.
- **Model:** имя, провайдер (выбор из списка провайдеров), `id` («defaults to the name»), `context` (не меньше 100000), `label`, `description` («defaults to via <провайдер>») и `settings` (YAML, по умолчанию свёрнуто). Внизу строка «Used by profiles: …».
- **Profile:**
  - `model`, `subagents` и каждый из `aliases` выбираются из списка. В нём сначала модели конфига, затем модели Claude: `opus`, `sonnet`, `haiku`, `fable` и пункт «другой `claude-…` ID» с полем ввода. В `aliases` алиасов Claude нет, только ID на `claude-`, как требует `config.Parse`. При `subscription: no` модели Claude недоступны;
  - `subscription` — «default», `yes` или `no`. Пункт «default» показывает итоговое значение с причиной («default: yes (opus is a Claude model)»). Страница вычисляет его по правилу graft: подписка включена, если `model` — модель Claude. Пока модель не выбрана, пункт показывает просто «default»;
  - `picker` — упорядоченный список моделей конфига с кнопками ↑ ↓ × и выбором для добавления;
  - `effort` — «from defaults: max» или уровень;
  - `settings` — YAML, `env` — таблица пар, `args` — список строк.
- **Defaults:** `effort`, `settings`, `env`, `args`.

Удаление идёт с подтверждением. Если на запись ссылаются, диалог перечисляет ссылающиеся записи, и после удаления у них появятся ошибки. Переименование — это правка поля имени.

### Ошибки

Каждая ошибка есть в списке, который открывает счётчик ошибок. Кроме того:

- ошибка с путём к полю (`profiles.mix.picker[1]`, `providers.x.key.env`, `profiles.mix.env.FOO`) стоит у этого поля или элемента списка;
- ошибка с путём к записи (`profiles.mix`) — в шапке формы;
- ошибка с путём к разделу (`profiles`) — у заголовка раздела в боковом меню;
- ошибка без пути — под верхней панелью.

Поле ищется по самому длинному совпадающему префиксу пути.

### Особые состояния

- **Файла нет.** В основной области: «No config yet at ~/.config/graft/config.yaml: add a provider, a model and a profile, then save», и три кнопки. На этапе 2 здесь экран первого запуска.
- **Формы не открываются.** Видны ошибки со строками файла (`config.yaml:12: …`) и подсказка «Fix the file in your editor: this page reloads it when it changes». Формы скрыты, опрос версии продолжается.

## Этап 2: путь новичка

### Экран первого запуска

Показывается, когда файла нет. В нём одна фраза о том, что такое graft, сетка карточек пресетов и карточка «Custom…». Карточка открывает диалог «Add provider».

### Диалог «Add provider»

Тот же диалог открывает «+» у провайдеров: на экране первого запуска выбор пресета уже сделан, а в меню его делают в диалоге.

- Имя и URL берутся из пресета, их можно поправить. Если имя занято, добавляется суффикс (`ollama-2`).
- Ключ — виджет ключа, см. ниже.
- Модели пресета — галочками: имя, `id`, окно, кнопка Test.
- Профили — галочка «One profile per model» (включена) и галочка `mix` «Opus on your Claude subscription, with these models in /model» (выключена). Имена профилей совпадают с именами моделей, при занятом имени добавляется суффикс.
- «Add to config» кладёт провайдера, модели и профили в черновик. На диск их пишет обычный Save. После первого сохранения появляется подсказка «Run `graft <профиль>` in a terminal».

### Виджет ключа

Виджет стоит в диалоге и в форме провайдера, и это и есть проверка ключа. Ключ никогда не уходит в браузер: туда попадают только состояние и отпечаток (первые 12 hex-знаков sha256, как в `graft check`).

- **`file`.** Путь по умолчанию — `keys/<провайдер>` в каталоге конфига, через `~`, если каталог в домашнем: `~/.config/graft/keys/ollama`. Состояние файла показывается сразу: нет файла, права шире 0600, отпечаток. Под ним поле для вставки ключа и кнопка «Save key», ссылка «Get a key at …» из пресета и команда для терминала с кнопкой Copy:

  ```
  mkdir -p ~/.config/graft/keys && (umask 077; cat > ~/.config/graft/keys/ollama)
  ```
- **`env`.** Виджет показывает, задана ли переменная в окружении `graft ui`, и её отпечаток. Если нет, подсказка: «Export it in the shell that runs graft, then restart graft ui».
- **`command`.** Запускается только кнопкой Run, потому что команда может спросить пароль в терминале, где идёт `graft ui`. Ключ, прочитанный командой, сервер держит в памяти до конца сеанса, по тексту команды, чтобы не спрашивать пароль на каждый тест. Чтение ключей идёт под мьютексом: две команды не спрашивают пароль одновременно.

`POST /api/key/write` пишет только в `keys/<провайдер>` каталога конфига; имя провайдера проверяется по правилам `config`. Ключ проверяется так же, как в `keys`: обрезка пробелов по краям, одна строка печатных символов ASCII. Каталог создаётся с правами 0700, файл — с 0600: временный файл, `fsync`, `rename`. Существующий файл заменяется только с `replace: true`; без него ответ 409 с отпечатком текущего ключа, и интерфейс спрашивает подтверждение. Файл ключа пишется сразу, до Save конфига: иначе тестовый запрос не смог бы прочитать ключ.

### Тестовый запрос

Кнопка Test стоит у модели в диалоге и в форме модели. Она работает на черновике, до сохранения, и не требует, чтобы весь конфиг был валиден: у новичка в диалоге профилей ещё нет.

- Сервер проверяет URL так же, как `config`, раскрывает путь ключа так же, как `config` (`~` и путь от каталога конфига), и читает ключ через `keys.Reader`.
- Запрос: `POST <url>/v1/messages`, заголовки `Authorization: Bearer <ключ>`, `anthropic-version: 2023-06-01`, `content-type: application/json`, тело `{"model": "<id>", "max_tokens": 16, "messages": [{"role": "user", "content": "Reply with one word: pong"}]}`. Без потока и без повторов.
- Транспорт — маршрутизатора: тот же прокси из окружения, тайм-ауты соединения и TLS по 10 с. Общий тайм-аут — 60 с.
- Ответ интерфейсу: статус, время, а для 2xx — текст первого текстового блока, не длиннее 200 знаков. Для остальных статусов — тело, не длиннее 2 КиБ. Каждое вхождение ключа в тексте заменяется на `<key>`.
- Успех — статус 2xx. Модель с рассуждениями может не успеть написать текст за 16 токенов, и это не ошибка.
- Подпись кнопки говорит, что запрос тратит несколько токенов.

### Preview

Вкладка Preview рядом с Edit у профиля. Сервер сливает черновик, проверяет конфиг и вызывает `plan.Build` с окружением `graft ui` и файлами настроек Claude Code из каталога, где запущен `graft ui`. ## Фронтенд

- Сборки нет. Модули ES отдаются из встроенной статики через `//go:embed`. Внешних запросов страница не делает: это запрещает и CSP.
- `vendor/htm-preact-standalone-3.1.1.module.js` — бандл `htm@3.1.1/preact/standalone.module.js`, около 10 КБ. Он экспортирует `html`, `render`, `h`, `Component`, `createContext` и хуки Preact.
- `vendor/pico-2.1.1.min.css` — `@picocss/pico@2.1.1`, `css/pico.min.css`. Pico оформляет обычные `<input>`, `<select>`, `<dialog>`, `<details>`, кнопки и сетку, у поля с `aria-invalid` показывает ошибку и меняет тему по настройке системы.
- Лицензии лежат рядом: htm — Apache-2.0 (`htm.LICENSE`), Preact внутри того же бандла — MIT (`preact.LICENSE`), Pico — MIT (`pico.LICENSE.md`). Go-тест сверяет sha256 вендоренных файлов с закреплёнными значениями: `72284e8e…` для бандла и `fbc9a63f…` для Pico. `eval` и `new Function` в бандле нет, так что строгий CSP ему не мешает.
- `index.html` объявляет пустую иконку (`<link rel="icon" href="data:,">`), чтобы браузер не просил `/favicon.ico`.
- Логика браузера сведена к минимуму. То, что есть, живёт в `draft.js` без зависимостей от DOM: места ссылок при переименовании, привязка путей ошибок к полям, признак несохранённых правок, имена-заготовки. Тесты — `internal/ui/jstest/draft.test.mjs` на `node --test`. Рядом со статикой лежит `package.json` с `"type": "module"`, чтобы Node читал `draft.js` как модуль ES. Node на раннерах GitHub уже установлен, в CI добавляется один шаг.
- Для разработки есть проверка в браузере: `internal/ui/jstest/smoke.mjs`. Он запускает `graft ui` и headless Chrome, проходит по странице через DevTools Protocol и сверяет файл после сохранения. Ему нужны Chrome и Node 22 или новее. Запуск — `make ui-smoke`, в CI его нет.
- Остальное — компоненты: верхняя панель, баннеры, боковое меню, формы разделов, поля (`Field`, `Select`, `ListEditor`, `PairsEditor`, `YamlField`, `KeySource`). На этапе 2 добавятся `Welcome`, `AddProvider`, `KeyWidget`, `TestButton` и `Preview`.

## Тестирование

### Автотесты

Тесты не ходят в сеть: `go test -race ./...` и `node --test`, в CI на Linux и macOS.

- **`edit`** — табличные тесты:
  - черновик из `config.example.yaml`, примера из README и файлов с ошибками;
  - правка скаляра сохраняет комментарии;
  - добавление, удаление и переименование записей;
  - `env`, `args`, `picker`, `aliases`, `key`, фрагмент `settings`;
  - неизвестные поля, якоря и ссылки на них;
  - стиль новых узлов, новый и опустевший раздел, пустые строки перед разделами;
  - файлы, для которых формы не открываются.

  Отдельно — инвариант «черновик → слияние → рендер → черновик» на наборе правок.
- **`ui`** через `httptest`:
  - отказ без токена, с неверным токеном, с чужим `Host` и `Origin`; заголовки CSP и прочие; лимит тела;
  - `config` для существующего, отсутствующего и сломанного файла; `validate` со `stale`;
  - `save`: 409, 422, `.bak`, права прежнего и нового файла, запись через симлинк, создание каталога, ответ 500 при несовпадении черновиков (через подменённое слияние);
  - этап 2: `key/write` (права, отказ без `replace`, путь только в `keys/`); `key/check` для `env` и `file` с подменённым окружением; `test` к ненастоящему провайдеру: заголовки, тело, обрезка, замена ключа; `preview` без единого чтения ключа.
- **Проверка uid:** разбор образца `/proc/net/tcp` и соединение от своего процесса на Linux, которое должно пройти.
- **`launch`:** общая функция текста плана даёт прежний вывод `--dry-run`. Эталоны `cmd/graft` не меняются.
- **`cmd/graft`:** `ui` с аргументом — ошибка; `ui` не читает конфиг до старта сервера.
- **JS:** `internal/ui/jstest/draft.test.mjs`.
- **Вендоренные файлы:** sha256 совпадает с закреплённым.

### Приёмка

Приёмка идёт в браузере.

- **Этап 1.** Сначала на копии конфига владельца через `--config`, потом на живом: правка каждого раздела, переименование и удаление, сохранение (комментарии на месте, `graft check` проходит), конфликт с правкой в редакторе, файл с ошибкой, отказ без токена.
- **Этап 2.** На чистом `HOME` с настоящим ключом: путь из сценария 1, затем `graft <профиль>`. Запросы тратят квоту провайдера, поэтому приёмка проводится только с разрешения владельца.

## Ограничения и риски

- Первое сохранение из интерфейса нормализует форматирование всего файла: пропадают пустые строки внутри разделов, выравнивание комментариев и пробелы внутри `{ }`. Прежняя версия остаётся в `config.yaml.bak`.
- Конфликт с правкой на диске не сливается: перечитать файл значит потерять правки в браузере.
- Неизвестные поля и поля не той формы правятся только в редакторе.
- Правка значения с якорем превращает ссылки на него в копии, и общее значение перестаёт быть общим. Правка поля со ссылкой тоже заменяет ссылку копией.
- Проверка uid есть только на Linux. На macOS защита держится на том, что ядро не отдаёт аргументы чужих процессов. Свои процессы и root считаются доверенными.
- При пробросе порта через SSH номер локального порта должен совпадать с удалённым.
- Пресеты устаревают. Неверный `id` ловит тестовый запрос, а список моделей надо сверять перед каждым релизом.
- Тестовый запрос тратит токены.
- Ключ из `command` сервер держит в памяти до конца сеанса `graft ui`. Команда спрашивает пароль в терминале `graft ui`.
- Preview проверяет файлы настроек Claude Code для каталога, где запущен `graft ui`. Профиль может стартовать в другом каталоге, с другими файлами.

## Вне рамок

- Подгрузка списка моделей от провайдера (TODO в коде пресетов).
- Перестановка и дублирование записей.
- Правка неизвестных полей и полей не той формы в формах.
- Вкладка с YAML всего файла.
- Слияние правок браузера с правками на диске.
- Доступ не с `127.0.0.1`, учётные записи и пароли.
- Запуск сессий и журнал маршрутизатора в интерфейсе.
- Windows.
