# graft на Windows: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** graft работает в нативной Windows 10 и 11 (x64, ARM64) так же, как на Linux, с `claude.exe` от официального установщика, ставится одной командой PowerShell, и его тесты идут на Windows.

**Architecture:** Различия систем собраны в нескольких местах: новый пакет `internal/osenv` (имена переменных окружения и переменная домашнего каталога), `launch.FindClaude` и `launch.Replace` (какой `claude` и как его запустить), `keys.shellArgs` (оболочка ключа-команды), `config.Tildify` и `config.ResolvePath` (пути), файлы `*_windows.go` и `*_unix.go` там, где код не компилируется на другой системе. Тесты Windows лежат в `*_windows_test.go`; их гоняет `wintest.sh` на виртуалке, а после пуша — CI на `windows-latest`. Релиз получает zip для Windows и `install.ps1`.

**Tech Stack:** Go 1.26 (`go.mod`), `go.yaml.in/yaml/v3` — единственная зависимость; страница `graft ui` без сборки, Node для её тестов; Windows PowerShell 5.1 для `install.ps1` и ключей-команд.

**Spec:** `docs/superpowers/specs/2026-11-27-windows-design.md`

**Что проверено при подготовке плана.** На виртуалке с Windows 11 x64:
- тесты прогнаны на копии ветки, где три Unix-вызова убраны; каждое падение ниже приписано задаче, которая его чинит;
- `claude.exe` 2.1.332 берёт домашний каталог из `USERPROFILE`, а `HOME` не смотрит;
- ключ-команда через `powershell.exe -NoLogo -NoProfile -Command`, запущенная из Go, ведёт себя как набранная в PowerShell: `"`, `'`, `$env:`, `&`, `|`, `;`, кириллица; `exit 3` даёт код 3, ошибка — код 1;
- на консоли (`ssh -tt`) `Read-Host` спрашивает в консоли, а в ключ попадает только напечатанное командой;
- команда для ключа из задачи 7 на консоли пишет файл одной строкой в ASCII без BOM.

Тел функций в плане нет: исполнитель пишет их по сигнатурам, правилам и тестам.

**Виртуалка.** `.superpowers/scratch/windows/wintest.sh` (git его не хранит) копирует рабочее дерево, закоммиченное или нет, на виртуалку и гоняет там Go. Без аргументов он выполняет `go vet ./... && go test ./...`. С аргументами — `go <аргументы>`, например `wintest.sh test ./internal/keys/ -run TestRead -v`. На виртуалке стоят Go 1.27.4 без C-компилятора (значит, без `-race`) и Claude Code 2.1.332 в `%USERPROFILE%\.local\bin`. Имя хоста и пути виртуалки есть только в этом скрипте и не попадают в файлы и коммиты репозитория.

**Модели исполнителей (если Subagent-driven):** задачи 1, 2, 5, 7, 8 — opus; задачи 3, 4, 6 — sonnet. Задачу 9 ведёт контроллер сам: ей нужны виртуалка и владелец. Итоговое ревью — opus.

## Global Constraints

- Модуль `github.com/zinin/graft`, Go 1.26, новых зависимостей нет: стандартная библиотека и `go.yaml.in/yaml/v3`. `golang.org/x/sys` не берём.
- Системы: Linux, macOS, Windows 10 и 11; amd64 и arm64.
- На Linux и macOS поведение не меняется, кроме трёх мест: `env` конфига отвергает переменные graft в любом регистре; файл ключа в UTF-16 даёт понятную ошибку; неудавшаяся ротация лога не лишает сессию лога. На Unix остаются `exec` в прямом режиме, `/bin/sh -c`, предупреждение о chmod и проверка соединений `graft ui` на Linux.
- graft никогда не запускает `claude` через cmd.exe: в Windows только `claude.exe`.
- Ключ-команда в Windows: `<SystemRoot>\System32\WindowsPowerShell\v1.0\powershell.exe -NoLogo -NoProfile -Command <команда>`. `SystemRoot` берётся из окружения, без него — `C:\Windows`. Без `-EncodedCommand` и без `-ExecutionPolicy`.
- graft и `install.ps1` не меняют PATH, файлы Claude Code и файлы оболочки.
- В Windows graft показывает пути с `/`: `~/…` внутри `%USERPROFILE%`, `D:/…` вне его.
- Вывод graft, тексты страницы, комментарии в коде, документация и сообщения коммитов — на английском. Коммиты в стиле репозитория (`feat(launch): …`, `test: …`, `docs: …`), с телом «зачем», без трейлеров атрибуции, с явными путями в `git add`.
- Репозиторий публичный: в файлах и коммитах нет личных имён хостов, адресов, имён пользователей и локальных путей.
- Стиль кода — как в graft: комментарии полными предложениями объясняют зачем, имена и идиомы — как рядом.
- Раскладка по системам: код, который на другой системе не компилируется, лежит в `*_windows.go` и в `*_unix.go` с `//go:build !windows` (суффикс `_unix` Go сам не понимает). Тесты раскладываются так же. Мелкие различия решаются через `runtime.GOOS`.
- Проверки после каждой задачи. Локально, через `build-forge:build-runner`: `test -z "$(gofmt -l .)"`, `go vet ./...`, `GOOS=darwin go vet ./...`, `GOOS=windows go vet ./...`, `go test -race ./...`, `node --test internal/ui/jstest/draft.test.mjs`. На виртуалке: `wintest.sh vet ./...` и тесты, которые задача называет в последнем шаге. С задачи 7 зелёный весь `wintest.sh`.

3. В PATH и `claude.cmd` от npm, и `claude.exe`, причём `.cmd` раньше: graft запускает `claude.exe`. Если есть только `.cmd`, graft отвечает ошибкой про пакетный файл. Проверяют `TestFindClaude` (задача 5) и `TestStartRefusesABatchClaude` (задача 5).

- [ ] **Шаг 4: Реализация**

- `parse.go`, `(*parser).env`. Сравнение с `OwnedEnv` без учёта регистра на всех системах (`strings.EqualFold`). Ключ, который `osenv.Equal` с одним из ранее встреченных ключей того же `env`, даёт ошибку `the same variable as <ранее встреченный> on Windows` (на Unix `Equal` совпадает только при одинаковых ключах, которых YAML не пропустит).
- `env.go`:
  - `unset`: кандидат считается унаследованным, если в `environ` есть имя, `osenv.Equal` с ним; «задана снова» — тоже через `Equal`.

- [ ] **Шаг 7: Владелец на рабочем столе виртуалки**

Короткая инструкция с командами:
- `graft ui` в Windows Terminal: браузер открывается сам, страница работает (значит, токен из фрагмента дошёл), Save key пишет файл, Test работает, команда для ключа копируется и работает в PowerShell;
- живая сессия `graft direct` в окне: Ctrl+C внутри Claude Code; закрытие окна не оставляет процессов (`tasklist` из другого окна);
- то же для `routed`.

Если фрагмент не дошёл, `openBrowser` в Windows переходит на `explorer.exe <url>`. Это правка задачи 1 с тестом и повтор шага.

- [ ] **Шаг 8: Уборка и отчёт**

Удалить `%USERPROFILE%\graft-e2e` и временные файлы стенда на виртуалке. Go и Claude Code остаются, они нужны для будущих проверок. Отчёт владельцу: результаты шагов 1–7, найденное и исправленное, и что осталось на потом. Например, задание установки для Windows в CI после первого релиза.
